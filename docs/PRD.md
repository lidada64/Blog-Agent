# PRD — Blog-Agent 产品需求与优先级

> 更新：2026-10-14。状态：本地语义RAG、回答策略与任务证据契约工程已实现；完整业务质量以 TASKS 和实际验收证据为准。
> 本文件是 Agent 产品范围、优先级和验收要求的唯一维护入口。网站 PRD 维护作品集页面；跨仓库协作见 integrations.md，技术拆分见实施计划。

## 1. 定位与目标

Blog-Agent 是核心工程项目，Carrykit 博客是作品集与业务接入载体。为非 admin 用户提供简单、有来源的博客/联网问答；为管理员提供保留原稿、可审阅的翻译整理与可靠发布。先交付可用链路，再完善交互和实验能力。

已有基础：本地关键词/文件检索与读取、只读 qa/manage CLI、可恢复会话、分项预算、用量观测及本地 Trace grading v1。完整质量评测、网页 MCP、网页对话框、网站 API、管理写入、语料库和彩蛋尚未交付。网站已有单篇中译英不代表 Agent 管理翻译已实现。

### 1.1 按重要程度排序的实施路线

排序依据：先解除阻断、交付用户明确要求的简单问答，再形成博客与管理闭环，最后做复杂体验和条件性优化。排名是默认认领顺序，依赖和上线门槛不能省略；原实施计划 P0–P9 保留为技术索引，旧九项排名由本表替代。

最短用户端链路：1 → 2（带基本硬限额）→ 5；博客问答增加 3 → 4，管理闭环增加 6 → 7 → 8 → 9。过程展示及优化不阻塞简单问答。权限、版本、基础观测和回归随相关功能完成，不因集中完善排名靠后而推迟。

## 2. 用户与权限

非 admin 用户：只读博客已发布文章及网页知识，查看回答与来源。管理员：管理原稿、待审稿、审批和获准的正式保存/发布。CLI 模式名不是身份认证；网站服务端执行身份、可见性和用户隔离，模型与网页内容不能授予权限。

## 3. 功能需求与验收

### 3.1 预算与可恢复问答

总预算内区分探索、回答与截断恢复额度；读取需满足问题的证据覆盖，任务成功以完整回答及来源为依据，不能以“读取过资料”代替。状态持久化且恢复不增额，明确无依据、部分资料、取消、生成失败及预算停止。D9 根因与现存证据由 [台账](project-highlights/README.md) 维护，修复与真实质量分别验收。

跨轮任务连续性（D7）：用户轮预算独立，任务目标、原始用户约束、候选、必需来源引用及未答问题跨轮持久化；明确续问复用活跃任务，明确文章返回可定位旧任务，切题不自动携带旧正文。来源重用前重新校验选定目录权限、内容版本及原文行；同文重叠读取只投影一次。统一上下文构建器记录本次输入可见范围、缺失来源及原因，回答引用仅核验可见范围；必需来源或约束装不下明确partial，不宣称完成比较。旧提示不自动升级；显式升级后可从旧完成轮的工具账本重建来源引用，未完成轮禁止升级。压缩首版采用同构建流程内的本地结构化任务整理，不调用付费摘要模型；原始历史、工具结果及精确历史索引保留。验收涵盖十轮续问/切题返回、原文更新/删除/越界、低额度覆盖、重启和中断恢复。复杂自然语言主题划分及真实生成质量独立复审。

### 3.2 本地 RAG

2026-10-15 D18实施范围（用户确认）：先分离RAG检索分块与正文引用章节。检索块仅帮助发现；引用只依据已读取且进入当前输入的正文、权限及版本。引用章节保留父子树，允许无直属正文的父章节引用实际可见子节；安全规范化标题外层Markdown样式，重名须用程序提供的版本绑定章节标识消歧，不能模糊接受不存在的来源。再完善引用错误的修复上下文：预算内一次重试接收失败草稿（有界、明确非证据）、逐项错误、当前可用引用及可见正文范围；每次投影重验来源，反馈与参考清单计入同一输入预算，空间不足明确停止而非盲重试。不增加总请求/工具额度，不让反馈成为新事实依据。旧提示显式升级，恢复不重置额度。验收嵌套标题、格式变体、重名、搜索未读、部分读取、过期/撤权、反馈可见性、低预算、取消恢复与旧提示兼容；真实语义支持与生成质量独立验收。任务路由、同题记忆匹配、目录问法与表达偏好不在本轮实施。

2026-10-13用户反馈后的回答契约：区分article、runtime、calculation、conversation与rewrite。身份/能力依据运行事实，明确的四则计算在受限本地表达式内验证，对话追溯依据本会话已保存的用户消息/可见回复，均不套文章引用门禁；不全局放行“常识”或模型自称有依据的文章事实。引用旧回答的压缩/改写须定位对应完成轮，把该轮可见回复作为待变换文本，不作为独立事实来源；有文章来源时重验权限/版本/模型可见范围。在旧来源有效且覆盖充分时不重新检索，按用户一句话/简短要求交付，格式失败最多一次预算内修复；无对应回答、旧回答本就失败、来源失效或输入不足时明确澄清/资料不足，不沿用旧结论。混合/含糊问题不能绕过文章权限，复杂开放领域常识不在本轮擅自扩展。旧会话需显式升级新契约，旧轮预算不重置。

2026-10-13用户确认：采用语义embedding与检索实现本地RAG，保留关键词/文件工具作为混合召回与回退。按Markdown标题/段落分块，保存文章ID、真实标题/章节、内容与embedding模型版本；片段向量化、查询向量化、相似召回、去重及预算内上下文组装。文章更新/删除与权限变更使对应索引失效。用户后续授权下载配置本地embedding；当前已接正式CLI/search_posts：隔离FastEmbed0.9.0/ONNX CPU、多语言MiniLM384维、本地SQLite向量缓存，BM25/文章级RRF混合与关键词回退。正常向量化离线，实际权重revision参与缓存隔离；配置和模型比较见[实施说明](local-semantic-rag.md)。本地检索集/工程回归已验，付费真实生成与人工语义来源支持仍待独立验收，网站数据尚未连接。

对外引用按文章/章节去重，在相关小节末或回答末尾显示，例如“引用自：*practical_guide_to_agent* **guardrail**”；不要求逐句引用，不默认展示行号、hash或原文摘录。缺章节时只引用真实文章标题，不编造章节。内部保留来源/版本/片段定位以支持追溯和评测，不以内部定位格式限制用户排版。回答可按任务使用标题、段落、列表、表格与示例，取消固定八条项目符号规则；能力/帮助依据当前功能与权限直接回答，不要求文章证据。

固定集保留D9回归，另冻结未见问题族，覆盖单篇、多篇、无答案、同义/错词/跨语言、长文代码、冲突与正文诱导；分别报告召回、回答正确性/可用性、来源支持与拒答。权限泄露/虚构来源阻断验收；embedding调用费用纳入总预算，权限及持久恢复保持。历史实施计划§26.2中冲突策略以后续实现任务按本节更新。

### 3.3 网站只读 API

网站提供经身份/可见性校验的列表、搜索与读取，Agent 通过文章来源适配器调用；隔离管理员草稿、公开文章及本地学习文件。验收未认证/越权、分页、版本变化、删除/撤回、断连与端到端引用；Python 不直接打开生产 SQLite。网站具体路由/模型实现前按其 ARCHITECTURE 更新。

### 3.4 观测与条件性扩展

Trace v1 继续复用，引用观测随检索、费用覆盖随实验、父子事件随 Subagent；规则通过不等于语义正确。语义评分须人工校准。语义/混合检索已按2026-10-13确认并入本地RAG完善，索引记录内容/切分/模型/权限版本，更新与删除失效，支持重建和关键词回退。Subagent 可关闭、独立上下文、无审批/发布权，父任务核验产物，父子预算和故障回归见实施计划 §24.2/§26。

### 3.5 缓存与成本/质量实验

按实际 provider/model 支持适配稳定前缀，使用服务端 cached token 证据，区分零命中与未知。固定模型/任务/评分，Cache/Compact 各配置至少 5 次，逐因素比较总费用、质量与耗时；计入摘要、重试、重读、全部模型请求及子任务，使用有日期的价格与费用完整性。保留失败样本，缓存权限不混用；缺失用量/价格不能宣称省钱。技术验收见实施计划 §24。

### 3.6 管理审批、发布与产品交付

P4 产出保真的双语整理稿、摘要、分类/标签及 slug 建议和资源问题；P5 网站审批绑定操作者、动作和内容/元数据/资源版本，修改后重新审批。服务端校验身份、旧版本和冲突，以 operation_id/请求指纹保存幂等结果，超时先查回执再决定有限重试。验收拒绝审批、审批失效、冲突不覆盖、成功但响应丢失后不重复发布。P6/P9 在单篇可靠后扩展批量任务、持久进度、worker 重启及部署/备份/回滚；完整故障清单见实施计划 P4–P6/P9。

### 3.7 文章结构化元数据（2026-10-12，待实现）

**已确认范围**：同时覆盖网站正式文章与 Agent/Blog 本地 Markdown；一篇文章至多一个主分类，可有多个标签。此次只记录需求与数据库建议，不代表 schema、数据库、页面或接口已经修改。预计阅读时长已纳入管理模式必做规划（见 §3.8），计算契约沿用本节，列表展示范围在 UI 实施时确定。

**数据库建议**：继续使用关系型 SQLite。网站复用现有 Prisma/SQLite，通过 Post 扩展及分类/标签关联表保存正式内容元数据；Agent 本地按需新增独立 SQLite 元数据库，正文继续以选定 Markdown 文件为准。两边使用相同字段语义与来源映射，不直接共用数据库文件，也不让 Python 打开生产 SQLite。网站连接阶段通过经鉴权 API 交换可见元数据。推荐理由：当前为个人网站、单机部署、低写入并发，已有 ORM、迁移和备份链路；此类字段需要关联、过滤与排序，无需另加 MongoDB、图数据库或向量库。未来多实例部署、持续并发写入或锁等待成为实际瓶颈时，再评估 PostgreSQL；WAL 不能消除 SQLite 单写者限制。参考 [SQLite 适用场景](https://www.sqlite.org/whentouse.html)、[WAL 并发说明](https://www.sqlite.org/wal.html)、[Prisma SQLite 支持](https://www.prisma.io/docs/orm/v7/core-concepts/supported-databases/sqlite)。这属于当前建议，具体部署/本地 schema 在任务认领时落实。

| 语料库回答 | 提醒后仍继续输入，达到降级阈值后切换到预设回答 | 不再调用生成模型或网页 MCP；从预先维护的语料条目中选择回答，提示当前为“预设回复”，不显示“联网”成功或伪装成实时回答 |
| 彩蛋并关闭入口 | 降级后持续输入达到关闭阈值，前端播放一次彩蛋，结束对话并关闭当前用户的 Agent 入口 | 先在服务端关闭该用户适用范围的 Agent 调用，再展示彩蛋；动画结束收起/禁用对话入口。刷新/并发请求不能绕过关闭，其他用户和博客浏览不受影响 |

**USER-6 分阶段额度与退出机制**：服务端维护正常 → 提醒 → 预设回复 → 关闭的单向阶段及累计消耗/有效输入次数，前端依据服务端状态展示，不靠隐藏按钮限制实际请求。提醒应早于硬额度耗尽；预设回复和关闭阶段不再产生模型或网页 MCP 调用。当前在途请求、取消和并发的处理规则在实施前确定，额度不足时不启动新调用；额度限制、阶段切换与操作记录同用户/会话范围绑定，不能影响管理员或其他访客。

**USER-7 预设语料库建设**：后续建立专门用于额度降级的静态回复集合，包括结束对话提示、常见问答、无法匹配问题时的通用回应和退出文案；支持中英内容、条目 ID 与版本，使用简单关键词/类别或顺序规则选择，不为此引入模型匹配或向量检索。回复只采用经维护确认的内容，不把用户聊天自动收录为公开语料；未命中时返回通用预设回应，不拼造与问题无关的事实。语料库未上线或条目不可用时，使用 i18n 中的固定结束提示兜底，不虚称已命中语料库。界面按钮/状态文案仍走 en/zh 字典；预设回答的数据位置在实施时确定。

**彩蛋与交互边界**：首版仅需一个简短、可跳过的效果，具体文案/视觉待设计；遵守设计 token 与 GSAP/useGSAP 规范，prefers-reduced-motion 下改为静态退出提示并关闭入口。彩蛋最多触发一次，不要求动画成功才关闭，不删除聊天内容、不关闭整个网站或浏览器。关闭后不继续接收 Agent 提问，允许继续浏览博客；何时重新开放依据实施前确定的重置/冷却策略。

**实施前冻结**：额度计量（消息/轮次、token、费用或组合）、作用范围（单会话或用户时间窗口）、提醒/降级阈值与降级后允许的有效输入次数、结束与关闭的恢复条件、语料条目及匹配规则、彩蛋形式。不得擅自写死数值或默认永久封禁，也不能通过“新对话”无限重置用户额度。此机制是用户端产品策略，不能替代 D9 的单轮探索/回答/恢复预算修复。

**验收**：用可配置的小额度样例按顺序触发提醒 → 预设回复 → 彩蛋/入口关闭；主动结束不触发强制彩蛋，空输入/重复请求不被重复计次；进入降级后模型/MCP 调用计数不再增长。预设命中/未命中/语料库不可用均有正确标识与回退；关闭后刷新、并发和伪造请求被服务端拒绝，其他用户可正常使用。彩蛋仅一次，取消/失败/reduced-motion 均能完成关闭；恢复严格遵循配置策略。完成实际页面与离线状态/预算回归。本轮仅登记规划，全部待实现。

#### 3.9.3 用户端对话缓存与刷新保留状态（2026-10-12，待实现）

**USER-8 / 用户要求**：记录用户端对话缓存，在一定保留时间内刷新页面，已有对话消息和当前会话 state 不被清空或重置；用户能继续原对话。具体保留时长待定，本轮只记录产品需求，暂不讨论存储位置、缓存技术或恢复实现。

**验收要求**：在约定有效期内刷新，原对话内容与会话状态仍在，继续提问沿用原会话；刷新不重置已有额度、降级或关闭状态，不能借此绕过 USER-6。不同用户的对话不互相可见。有效期长度、计时起点及过期后的产品行为留待后续确认，不默认永久保存或跨设备同步。本需求尚未实现，也不等同于模型 Prompt Caching。

#### 3.9.4 显式退出 Agent 对话（2026-10-14，待实现）

**USER-9 / 用户要求**：对话框提供明确可见、可通过键盘操作的“退出对话”按钮，让用户主动停止与 Agent 对话。退出结束当前对话；USER-2 的“停止生成”仅取消当前回答，两者语义与状态须明确区分。

**验收要求**：空闲或回答进行中均可退出；进行中退出时取消当前请求，停止后续模型/MCP 调用及消息追加，界面显示已退出状态。服务端确认退出，已发出的调用若无法立即取消，其迟到结果不得重新打开对话或追加消息；取消失败须明确提示。保留已有消息，不触发 USER-6 强制退出彩蛋、不关闭网站；刷新在 USER-8 有效期内保留退出状态。重新开始须由用户显式操作，并遵守原有额度与恢复规则，不因退出重置额度；不影响其他用户或管理员。按钮与状态文案同时纳入 en/zh 字典。仅登记需求，具体交互与实现后续验收。

#### 3.9.5 统一 Agent 开场白（2026-10-14，待实现）

**USER-10 / 用户要求**：Agent 新对话采用统一维护的开场白，简短介绍身份、当前可用能力及如何开始提问。同一语言、同一业务模式使用一致文案；问答与管理模式按实际权限说明能力，不宣称尚未接入或未授权的功能。具体开场白文案待实施时确定。

**验收要求**：首次进入新对话及显式重新开始时展示一次；连续追问、刷新恢复原对话、停止生成或已退出状态不重复追加开场白。开场白使用统一的 en/zh 文案入口，不由模型每次随机生成，不为展示开场白调用模型/MCP；语言切换不新增重复消息。展示开场白不重置额度，也不将其计为用户提问。验收新建、恢复、退出后重新开始及双语一致性。仅登记需求，尚未实现。

## 7. 可选扩展

### 7.1 humanlizer：文章语言润色（待实现）

- **任务名称**：humanlizer（对应常见拼写 humanizer，保留用户命名）。
- **目标**：在博客整理与翻译流程中提供可选的语言润色，减少模板化表达、空泛措辞和生硬句式，保留作者个人语气，使文章自然易读。
- **范围**：处理用户主动选定的原文、整理稿或译文；保留观点、事实、专业术语、代码、链接和引用，不补造经历、数据或来源。
- **执行方式**：管理模式中的可选步骤，可跳过；输出独立待审稿及修改说明，支持对照、人工修改和拒绝，不直接覆盖原稿或自动发布。后续实现可评估复用 humanizer skill，具体接入方式在任务认领时确定。
- **实施时机**：在优先级第 7 项的待审整理/翻译链路可用后实施，复用已有审稿与权限机制；无需等待 Subagent 或批量产品化。
- **验收**：中文与英文固定样例均有前后对照；观点与事实不变，术语、代码、链接和引用保持完整；用户可选择保留原稿或接受修改；应用执行层阻止未批准的覆盖/发布；额外模型调用纳入费用与耗时记录。自然度通过人工审阅记录，不宣称未经验证的质量提升。
