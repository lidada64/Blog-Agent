## 目标与首版边界

首次配置文章知识库时自动建档并排队构建全部文章的章节/整体摘要；后台自动检测文章新增、修改、删除并定向更新，无需用户提问或手动刷新。此处初始化是选定posts_dir并创建知识库配置，不是git init，也不通过Git hook触发。

首版使用本地Python独立工作进程＋SQLite持久任务队列；沿用现有依赖，采用可配置轮询，不新增文件监听、消息队列或服务框架。建议初始扫描间隔30秒、稳定等待2秒、生成并发1，作为可调工程默认值，不是性能保证。操作系统/进程不运行期间不执行，重启后补扫；开机自启部署另行配置，不用Codex聊天定时任务代替产品后台。

## 自动生命周期

1. 用户一次性配置文章根目录、后台摘要模型及维护总额度。配置缺失仍可建立目录/原文索引，摘要任务进入blocked_config；状态明确列出缺项。开发者可以先完成全部离线实现，真实付费摘要在额度明确后运行。
2. 初始化入口及普通Agent启动均调用ensure_worker：按根目录和权限作用域查进程心跳，已有健康工作进程则复用，没有则自动启动独立无窗口进程。停止前台问答不停止后台工作进程；提供显式status/stop维护入口，并区分“用户暂停”与异常退出，暂停期间不偷偷重启。
3. worker启动先做完整对账：首次建库扫描全部文章；已有库恢复未完成任务并补查停机期间的变化。后续周期性扫描持续发现变更，不等待下一次问答。多个前台同时启动只能得到一个有效worker租约；租约接管使用递增令牌，旧worker不可提交结果。
4. 工作进程自动启动时记录可定位的本地日志、PID/心跳及退出原因；父进程确认启动成功才显示“后台运行”。无后台执行条件时如实报告，不把待排队说成正在处理。

所有状态与摘要位于忽略目录.blog-agent-data/。首版建议独立article-memory.sqlite3统一保存文章/章节摘要和任务，避免修改现有向量表；每条记录带scope，不跨模式/目录共享可见摘要。新增身份体系后scope还需包含身份/可见性版本，不能仅凭模型自报权限。

## 数据与一致性契约

最小实体：libraries（根目录、scope、扫描状态/代次、维护配置）、documents（文章ID、当前检测版本、已发布摘要版本、状态）、nodes（版本、节点ID/父ID、类型、范围、内容hash、摘要、生成版本、依赖）、jobs（幂等键、状态、租约、重试与next_run_at）、usage（请求ID、预留、实际消费及未知消费）。表结构和迁移需带schema_version。

文章ID首版沿用规范相对路径；重命名按删除＋新增处理，正确性优先，不承诺自动跟踪重命名。节点摘要缓存键包含作用域、节点正文、标题/父级语境及解析器/模型/提示版本。仅正文hash不足以处理同段文字移动到不同语境；章节变化时保守重建受影响依赖。跨版本复用摘要文本时也必须重建本版本的范围和章节映射。

扫描返回完整清单及complete/issues/scan_epoch。mtime/size可以预筛选，但内容hash决定版本；需定期完整hash对账以发现同大小/时间戳变化。枚举截断、目录不可访问、文件读取失败均不能触发批量删除；只有完整且成功的对账确认缺失才写删除标记。读写竞态以稳定重试和提交前再核对源版本处理，不只依赖等待两秒。

| 变化 | 必须执行 | 可以复用 |
| --- | --- | --- |
| 首次初始化 | 全量建目录/版本，所有文章排队 | 已持久完成的同版本节点 |
| 新文章 | 仅该文章解析、章节摘要、整体摘要与索引更新 | 其他文章全部保持 |
| 单章修改 | 该章及父级依赖、整体摘要，当前版本定位/目录 | 内容及语境均未变的章节摘要 |
| 章节结构调整 | 更新章节树、编号映射、失效的祖先摘要 | 匹配可靠且语境未变的节点 |
| 删除/权限变化 | 立即阻止读取相关摘要；对账后清理可见索引 | 无权继续返回旧摘要 |
| 配置/模型/提示版本改变 | 按生成版本排队重建 | 不把旧生成版本悄悄标成新版本 |

构建采用快照：块→章节→文章，正文块各自在输入上限内处理；文章有大量章节时再分组归并，不能在最后合并时重新超限。保存关键断言、限定条件及来源映射。代码/表格过大时定义结构保留策略或失败状态，不静默截掉后声称完整。

事务发布条件：所有依赖ready，摘要结构验证通过，源版本仍为目标版本，worker令牌有效。短事务内切换active_version；模型请求在事务外。构建过程中又发生更新，则旧构建superseded，新版本排队；不发布混合版本。读取时重新验证当前文件版本与权限，轮询尚未发现变化也不能交付陈旧摘要。原文只读，构建失败不修改用户文章。

## 任务、费用与恢复

任务状态区分pending/running/retry_wait/ready/failed/superseded/blocked_config/blocked_budget，文档另有stale/deleted。幂等键至少含scope、文章目标版本、节点及生成版本；重复事件合并，已完成节点不重复生成。有限指数退避；单篇失败不阻塞其他文章。租约过期的任务可接管，提交必须检查令牌。

调用前持久预留后台请求数、输入/输出及费用上界，调用后落实际用量；重试、摘要和嵌入都入账，重启不补充额度。提供已用/预留/余额状态。请求超时或进程在响应前崩溃时可能已经计费：未知消费继续占用保守额度，记录请求ID并有限重试，不能宣称外部调用“恰好一次”。前台问答额度与后台额度分别限制，再汇总项目总消费；不要复用历史授权的测试额度。

## 按阶段实施与完成判据

| 阶段 | 产出 | 必须通过的验收 |
| --- | --- | --- |
| A：版本库与自动发现 | schema/扫描差异/持久队列/初始化标记，模拟生成器接口 | 初始化一次；重启不重复排队；新增/修改/删除；扫描失败不误删；超限不假完成 |
| B：后台自动生命周期 | ensure_worker、单实例租约、循环扫描、status/stop/恢复 | 无用户问答也能发现修改；关前台后继续；并发启动不重复消费；暂停有效；崩溃接管 |
| C：分层构建与预算 | 可替换生成器、块/章节/整体依赖、增量复用、原子发布 | 只改一章不重做其他无关章；构建中再次修改；旧worker提交拒绝；未知计费保守预留；重启额度守恒 |
| D：前台消费 | 有界总览/章节读取工具、派生证据校验、选章绑定 | 总览＋真实目录＋选章；直接指定章节；跨轮/重启编号绑定；失效拒用；细节回原文 |
| E：质量与运行验收 | 固定语料/问题集、真实摘要抽查、生命周期演示 | 中尾部事实、限定条件、代码表格、跨文差异、冷/热成本和延迟分报 |

每阶段使用临时合成文章和模拟模型先验证；不把模拟生成器接成生产摘要。A–D离线实现可以连续推进，无需因尚无真实模型额度而停在设计。E的真实调用需要明确当次模型及总额度，缺失时如实列出剩余验收，不宣称生产可用。提交前运行python code/evaluate_agent.py --mode offline，并检查暂存文件无凭据/文章/运行结果。

每阶段用仓库challenge-log skill更新D7/D9/D12的执行者、假设、操作、观察、结果和取舍，失败尝试也保留。每次更新先运行容量planner，再维护分级索引；只有实测改善才写简历收益。
