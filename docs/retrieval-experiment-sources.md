# 检索与 Subagent 实验：一手来源笔记

查阅日期：2026-10-12。用途：给本项目的实验手册提供外部依据；这里没有运行实验、调用付费模型或读取用户文章，不能把外部结果写成本项目已获得的收益。

## 1. 复杂问题是否需要 Subagent

**来源证据**：Anthropic 的研究系统工程报告认为，多 Agent 尤其适合可独立开展多个方向的广度研究，以及信息超出单个上下文的任务；需要共享大量上下文或存在密集依赖的任务较不适合。它们也遇到重复搜索、任务遗漏、协调及恢复复杂度。该报告中约 15 倍 token 的参照物是普通聊天，不能写成相对单 Agent 的固定倍数，更不能套成本项目的成本预测。[How we built our multi-agent research system，2025-06-13](https://www.anthropic.com/engineering/multi-agent-research-system)

**本项目推论，待验证**：多篇引用本身不构成启动条件；若能一次检索、批量读取并集中回答，单 Agent 可能已足够。候选触发条件应是存在可独立求证的子问题、单上下文难以容纳证据或确有并行延迟收益。子 Agent 回传应包含结论、原文证据定位、未解决问题和用量，父 Agent 应核对原始证据并完成最终综合。不能只收摘要后相互转述。

**实验含义**：先建立可靠单 Agent 基线，再在同一多源题目上比较“串行工具”“并行/批量工具”“有限 Subagent”。同时报告相同总预算的公平比较，以及不同预算下的质量—成本曲线；父子全部请求、证据重复和综合阶段均计费。保持最终回答与失败恢复额度，禁止子任务独立扩张总预算。

## 2. 关键词、语义和混合检索各解决什么

**来源证据**：Anthropic 的 Contextual Retrieval 报告指出，关键词检索能补充语义检索对精确标识符/技术术语的遗漏；分块可能损失解释该片段所需的背景。它们比较了 embedding、BM25、背景补充、top-K 和重排组合；在其数据中组合与重排降低检索遗漏，但重排增加运行时延迟和成本，分块边界及 top-K 需要针对应用评测。[Introducing Contextual Retrieval，2024-09-19](https://www.anthropic.com/engineering/contextual-retrieval)

**本项目推论，待验证**：中文、英文、混合术语、拼写错误、同义改写以及精确代码名必须分别评测；不能由外部报告推导语义检索一定优于关键词。正文分块应保留文章标题、章节、版本及引用位置，补充相邻段落作为独立变量。自动生成片段背景是一项额外的预处理费用，应另设实验组，不能混入语义检索基线。

**实验含义**：关键词、纯语义、混合三组先共用同一分块与证据总 token 上限；分别改变检索器、top-K 或相邻扩展，避免一次改变所有因素。重排作为后续消融变量，先证明有实际质量收益再考虑启用。

## 3. 混合检索的最小可比较实现

**来源证据**：Elastic 官方文档描述将全文和向量搜索结果合成一个排名列表，并推荐其产品使用 RRF。RRF 根据排名融合，因此无需把两种检索器的原始分数直接相加。[Hybrid search，文档无明确发布日期，查阅 2026-10-12](https://www.elastic.co/docs/solutions/search/hybrid-search)

**本项目推论，待验证**：可以把“关键词候选 + 语义候选 + 去重 + RRF + 有界证据返回”作为混合实验基线；这不是建议引入 Elasticsearch 或新数据库。针对同文相邻块、重复块和多个版本，需要先按稳定证据身份去重，权限过滤须在两个检索分支都执行。

**实验含义**：记录两个分支候选数、融合后有效证据数、重复率、全文/段落返回 token、检索耗时；不同检索器命中同一证据不能重复注入。未命中时要明确无结果，不能让检索器无界改写查询。

## 4. 为什么不能只测少量技术词

**来源证据**：BEIR 作者在不同任务和领域构成的 18 个数据集上评估多类检索系统，发现 BM25 是稳健基线；重排及 late-interaction 平均效果较好，但计算成本较高。这是跨领域零样本检索研究，不是本项目中文博客问答评测。[BEIR: A Heterogenous Benchmark for Zero-shot Evaluation of Information Retrieval Models，初稿 2021-04-17](https://arxiv.org/abs/2104.08663)

**本项目推论，待验证**：必须覆盖单篇解释、全文总结、精确定位、同义表达、跨篇比较、多跳依赖、冲突版本及无答案；只测能在原文中找到同一词的题目会偏向关键词。检索 Recall 变好也不能自动代表最终答案连贯、完整、有正确引用。

**实验含义**：按题型与文章大小分层报告证据召回、引用支持、任务完成率和答案连贯性，再报告费用、延迟及失败恢复。测试集与调参集分离；复杂问答采用人工定义的必要事实/必要证据覆盖标准，不强行要求唯一表达或唯一检索路径。

## 5. 外部依据的使用边界

- 这些来源支持候选架构与实验变量，不提供本项目的全文阈值、最佳 top-K、最便宜检索器或 Subagent 触发阈值。
- 费用需要从实际选择的 provider、模型、账户计价与真实 usage 计算。预处理、增量更新、查询 embedding、重排、回答、恢复、评审及所有子任务分开列账；未知 usage 保留未知。
- 检索实验先冻结生成模型与预算；全文/章节/段落分支实验先冻结检索器；Subagent 放在单 Agent 返回策略与检索器结果稳定之后，减少归因混淆。
- 每一结论标成“外部来源”“项目假设”或“本项目实测”。实测还需附配置、语料快照、结果文件和重复次数，外部百分比不作为验收指标。
