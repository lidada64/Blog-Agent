# 多轮记忆与上下文 · M01–M10

返回[题库入口](README.md)。每组独立会话，组内连续执行；编号表示用户轮。操作步骤不发送给模型。涉及 compact、重启、输入限制的用例必须有运行事件佐证；只说“假装已经压缩”无效。

这些题测应用层记忆、上下文组装、来源复用和模型遵循能力的组合。仅凭答对不能归功于模型本身，更不能证明永久记忆。记忆中保留了什么、实际输入包含什么、回答使用了什么，要分开记录。

## 固定干扰块 D（逐条发送）

下列六轮可原样复制，保证重复实验可比较；不要用每次变化的“随便聊一些别的”替代。

1. `计算 17 加 26，只给结果。`
2. `把“蓝色书签”翻译成英文，不作解释。`
3. `把 8、3、5 按从小到大排序，只给排序结果。`
4. `把下面这句话改成礼貌的请求：把窗户关上。`
5. `只回复两个汉字：收到。`
6. `给书桌上的小台灯起一个不超过四个汉字的名字，只给名字。`

D 的简单任务是干扰，也单独记录其路由/格式是否失败；当前若被文章证据守卫错误拒绝，应登记 D11/D12 类型，不隐藏这类失败。无论中间是否失败，继续执行目标回忆轮，避免只保留顺利样本。

## M01 · 多轮干扰后，一句话总结 MCP

**输入序列**：

1. `根据博客解释 MCP 的作用、工具调用流程和审批位置；回答后记住：本次讲解面向第一次接触 Agent 的人。`
2. 逐条发送干扰块 D，共 6 轮。
3. `回到你最初对 MCP 的回答，面向同样的读者，用一句话总结 MCP 的作用；不要列点，来源如需展示就放在这句话的括号里。`

**注释**：共 8 个用户轮；MCP 来源。目标是用户举例的可复现版本，同时考查切题返回、早期任务定位和“一句话”约束。

**判定**：内容与首轮解释及原文一致，适合新手，一句完成。首轮 MCP 若未成功，最终内容仍可独立计分，但“回忆首轮”的结论记受阻，不能用最终通用定义证明记忆成功。

**定位**：记录首轮证据是否持久化、最终请求是否含有效原文/任务引用；补读可以通过正确性，但另记额外成本。若目标信息根本未进入输入，不能一概归因于模型忘记。

## M02 · 用专有标记区分回忆和常识

**输入序列**：

1. `仅在当前会话中记住：我的测试项目代号是“青柚-47”，我把 MCP 类比成“工具接线板”，我喜欢先结论后解释；这些是我给你的设定，不是博客事实。请简短确认。`
2. 逐条发送 D。
3. `请返回我最初设定的项目代号、MCP 类比和回答偏好，恰好三条；只复述我说过的，不补博客来源。`

**注释**：回忆信息在公共知识里无法推断；比单独问“还记得 MCP 吗”更能检验会话记忆。

**判定**：三个字段与原设定一致，区分用户设定与文章证据；不能引用一篇文章来“证明”代号。禁止从评分器向最终输入额外注入正确答案。更换代号做重复实验时冻结代号表并留在评审端。

## M03 · 约束持续、修改与局部生效

**输入序列**：

1. `这段会话默认用中文、最多三条回答，并标注博客来源；先根据文章解释 RAG。`
2. `根据文章解释 MCP，沿用刚才的要求。`
3. `只在这一轮改成英文、恰好两条，比较 RAG 和 MCP；来源要求不变。`
4. `回到默认要求，解释 compact 的作用。`

**注释**：RAG/MCP/STATE；测约束不是简单覆盖或永远累加。

**判定**：第 2 轮继承中文与条数上限，第 3 轮英文两条，第 4 轮恢复中文最多三条；四轮内容/来源均正确。不将第 3 轮临时英文偏好永久保存。

## M04 · A → B → A，恢复未完成部分

**输入序列**：

1. `我要比较 Prompt Cache 和 Conversation state and Compact；现在只解释它们各自解决什么问题，暂时不要讨论取舍。`
2. `换个话题，根据 MCP 文章解释审批在调用流程中的位置。`
3. `继续刚才两篇关于缓存和压缩的比较，补上我们还没讨论的取舍；不要重新整篇介绍，也不要把 MCP 审批当成比较主题。`

**注释**：CACHE/STATE → MCP → CACHE/STATE；测旧任务选择、未答点和来源切换。

**判定**：准确回到两篇，讨论窗口、证据、复用和费用的权衡；不把新问题默认为最近的 MCP。最终请求应装入对应任务的有效证据，不能只有一条模糊摘要却声称双文比较完整。

## M05 · 纠正自己的设定，不篡改原文

**输入序列**：

1. `本测试暂定：项目代号是“青柚-47”，目标读者是专家；请根据博客简述 MCP。`
2. `更正我自己的设定：项目代号改为“白鹭-62”，目标读者改为新手，旧设定不再使用。`
3. `比较博客里的 RAG 和 MCP。`
4. `现在用一句话向当前目标读者介绍我们的项目，并包含当前代号；项目功能仅说“学习 MCP”，这是测试设定。`

**注释**：测有效用户设定更新与旧值失效；不允许把用户设定写成博客原文事实。

**判定**：只用“白鹭-62”，表达面向新手，不带旧专家设定；一句话，功能范围没有扩大。对比 M02，可区分“保存不了”与“保存后不更新”。

## M06 · 历史精确回顾与代词歧义

**输入序列**：

1. `请根据博客分别解释 MCP 与 Function Calling；把我的测试标记“松塔-19”保留在本轮回答末尾。`
2. `请分别解释 compact 与 memory 的作用。`
3. `它和那个有什么区别？`
4. `我指第一轮中的 MCP 与 Function Calling，请用两条比较。`
5. `我在第一轮给的测试标记是什么？只输出标记；这是回顾我们的对话，不是问文章。`
6. `请原样复述我第一轮完整的提问；如果无法读取原话，请明确说明，不能把概述冒充逐字复述。`

**注释**：MCP/FUNCTION/STATE/CONTEXT；测合理澄清、按轮定位、精确历史与概述的区别，关联 D12。

**判定**：第 3 轮先澄清或明确给出有条件的解释，不无声地假定唯一对象；第 4 轮消歧成功；第 5 轮精确返回标记；第 6 轮逐字符对比用户原话，若能力不足可安全承认但历史检索维度不通过。不能把检索不到文章当作回顾历史失败的唯一理由。

## M07 · 真正压缩前后，三类信息是否保留

**输入序列/操作**：

1. `会话约定：测试代号“海盐-83”；只用中文；这项比较最终最多三条。根据 Prompt Cache 与 Conversation state and Compact，先列出各自作用，留下“怎样兼顾窗口与缓存”暂不回答。`
2. 执行一次 D；测试驱动在独立会话中触发当前实现支持的真实 compact。若使用阈值触发，按 D 的固定顺序重复直到首次成功压缩，记录重复数和总输入；不能预设发六句一定会触发。
3. `继续之前留下的比较问题，保持原定格式和语言，并把测试代号写在首条；依据之前两篇文章，来源放在相应条目里。`

**注释**：同时测精确标记、用户约束、未答任务和双文事实，关联 D7。与禁用/未触发压缩的配对会话比较。

**判定**：有成功 compact 事件；代号/语言/三条限制保留、未答点被完成、两篇当前有效来源可核对。若没有实际 compact，记 BLOCKED，不能称压缩记忆通过。当前 Blog 本地整理不能冒称执行了付费摘要或服务端 compact。

## M08 · 关闭进程后续问

**输入序列/操作**：

1. `本次任务代号“石榴-26”；根据 MCP 文章先讲工具发现，下一轮再讲审批；始终用中文短答。`
2. 等待第 1 轮持久保存成功，记录状态文件/提示版本/账本；正常关闭测试进程，从同一测试状态恢复。
3. `继续未讲完的部分，先给出任务代号。`

**注释**：测磁盘持久化与恢复；不能只在同一模型会话里声称重启了。

**判定**：代号和审批未答点恢复，来源重验，已有消费不消失；这是一条新用户轮，可按规则有新轮额度，但会话/实验总消费不能重置。恢复动作本身不重复执行已完成调用。不与 B08 的中途取消混算。

## M09 · 记忆不能压过更新后的原文

**准备**：临时语料仅两篇合成文档：《缓存实验》写“本样例保留周期为 10 分钟”，《压缩实验》写“工作摘要保留当前目标和未答点”。记录初始 hash。

**输入序列/操作**：

1. `根据缓存实验，保留周期是多少？请给来源。`
2. 测试人员把临时《缓存实验》改成“本样例保留周期为 20 分钟”，记录新 hash，不把新值写入下一轮问题。
3. `重新确认刚才文章当前写的周期，并说明与上一轮是否变化。`
4. 测试人员删除临时《缓存实验》或通过实际权限层撤销其可见性；两个变体分开运行。
5. `再按这篇文章目前的有效内容回答周期。`

**注释**：精确合成事实，便于判分；测来源新鲜度及撤回，关联 D7。这里的数字只用于夹具，不是 provider 缓存规则。

**判定**：第 3 轮重新取证并用 20；第 5 轮说明当前不可核查，不再引用已失效文档。允许明确区分“历史曾写什么”与“当前无依据”，禁止伪称已重新读取。权限撤回夹具不能只靠模型口头答应。

## M10 · 旧提示会话与显式升级

**准备**：用受支持的旧提示版本创建独立测试状态，完成一次问题；不要手工篡改用户状态或伪造版本字段。

**输入序列/操作**：

1. `根据博客解释缓存命中，下一轮再谈 compact 的影响。`
2. 保持旧状态恢复，输入：`继续之前没谈的部分。` 记录旧能力和工具集合，不要求旧版本具备新能力。
3. 完成当前轮后，通过已有显式升级入口升级该测试会话；再次输入：`请结合之前的两部分，把缓存与 compact 的关系整理成三条。`
4. 另建旧版“未完成轮”夹具，尝试升级，检查是否要求先恢复完成而非混用协议。

**注释**：测版本隔离、工具协议和历史引用重建，非靠提问本身能完成的测试。

**判定**：未授权升级不静默发生；完成轮升级后使用新版本一致的协议，历史证据必须重验；未完成轮不强行升级，恢复消费不增额。无法准备受支持旧版本时记 BLOCKED，不拿新会话模拟通过。
