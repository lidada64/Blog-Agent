## 已确认的问题

用户问题为“现在我的库里有哪些文章”，属于目录查询。会话最后状态为 max_steps：单轮 8 次模型请求用完；34 次 find_file、2 次 search_posts，未调用 read_post，未生成最终答案。最后模型请求正常完成，输入 10,263 token，没有上下文超限错误。

当前目录有 19 个顶层 Markdown；工具只检索当前层，子目录不是本轮默认范围。find_file 最多返回 5 项及 truncated 标记，没有总数、分页或目录工具。模型从 `.md` 查询转向猜文件名关键词，不能通过同一工具可靠遍历剩余结果。

已有约束包括目录边界、只读权限、参数、文件数量/大小、输出长度和步骤上限。缺少的是任务匹配的工具接口、进度反馈及预算结束时的收尾。接口缺口有证据；不同提示/模型下的具体循环诱因仍需固定任务对照，不把单次样本归因为某个模型能力缺陷。

## 第一阶段：目录查询独立路径

新增 list_posts，按权限范围返回元数据目录，不把“有哪些文章”当作全文问答：

- 输入 limit 与 cursor；返回 items、total、next_cursor、snapshot_version，以及读取异常/遗漏说明。items 至少包含 post_id、标题、source、version，不返回正文。
- 在选定目录的现有数量上限内稳定排序，分页限制返回长度；这次 19 篇可在 limit=20 的一页完成，不默认读取子目录。
- cursor 绑定目录范围与目录快照版本；文章增加、修改或删除使旧 cursor 失效，显式提示重新列举。分页重启次数也受预算限制，持续变化不能无限重试。
- 目录任务的完成条件为 next_cursor 为空，或用户主动要求只展示前 N 项；仍有下一页时明确“当前仅列出部分”，不声称全部。
- 该工具可确定性分页组装结果；无需模型猜文件名，也无需为了列标题读取整篇正文。模型用于意图理解或展示润色时同样占用请求预算。
- 列举只提供 metadata，不放宽现有 find_text 的 find_file 发现前置条件。实际 read_post 和后续网站接口仍独立校验权限与版本。

检索目录与正文问题要分别路由：目录列举 → list_posts；已知文章 → read_post；按内容提问 → 检索/读取流程。意图不明确时只澄清必要信息，不自动遍历全库。

## 第二阶段：正文问答的有限流程

默认链路：问题 → 检索候选 → 读取有来源的片段 → 回答。自主补查作为受预算约束的可选分支，不开放无限文件探索。

起始策略建议（尚未冻结，需用固定任务校准）：初次检索取 Top-3，读取相关片段；缺少必要依据时最多一次有理由的改写或补查。复杂多篇问题可使用不同预算配置，不能把所有任务一律限制为同一篇数。

进度以新文章/片段 ID、内容版本和已核对的目标事实衡量，不以“又调用一次工具”衡量。对候选与读取片段去重；相同查询和相同数据版本复用已存结果；连续补查没有新增证据则进入收尾。新增证据不能自动等同于答案充分，引用与事实支持仍要校验。

查询规范化必须保留真实检索语义，首版优先精确参数去重；不随意删标点或将不同关键词视为相同。数据版本变化时失效旧结果，避免复用过期证据。

## 第三阶段：运行时预算与收尾

目前 Trace grader 在事后检查预算；后续还需在运行时约束每轮模型请求、工具调用、补查次数、耗时和活跃上下文大小。并行调用的每个工具都计入预算，模型一轮返回五个调用不能只算一次工具额度。

预算应保存到检查点：resume 延续本轮已消耗额度，不能每次重启自动重置。用户显式扩展预算需记录为新的授权配置；预算重置不是恢复的默认行为。

预留一次最终回答的模型请求与输出额度，达到探索阈值后在代码中关闭检索工具，基于实际证据收尾：

| 情况 | 返回行为 |
| --- | --- |
| 已有充分证据 | 回答并附已读取来源 |
| 只有部分依据 | 给出有支持的部分，明确未知点与检索范围 |
| 未找到支持材料 | 说明选定资料中未找到依据，避免编造 |
| 请求过宽或歧义大 | 明确需要缩小的范围，询问一个必要问题 |
| 最终生成也失败 | 用程序输出停止原因和进度摘要，保留恢复状态 |

任务结果 completed/partial/no_evidence/budget_stopped 与技术状态分开记录；安全停止或诚实的部分回答不等于完整任务验收通过。结果模型与评分器应一起更新，不能为了消除 FAIL 改成虚假的成功。

## 第四阶段：单轮活跃上下文管理

当前 local 压缩保留最近两轮，在只有一个用户问题时通常无法缩减该轮连续搜索历史。它不是通用的单轮工具结果压缩机制。12,000 的阈值单位是 UTF-8 字节，不是模型 token 上限。

保留完整历史与工具结果账本；活跃上下文只装载当前问题、已选证据、必要调用/返回对及可回读的摘要/定位。不得截断未完成调用配对，也不能在摘要里把未读内容变成已验证事实。

按实际 provider/model 核实上下文限制并预留输出空间；缺失 tokenizer 或 usage 时明确计量方式，字节数只能是保守的工程限额。不能把这次约 10k token 当作所有模型的安全阈值。

## 验证与实施顺序

优先：目录工具与分页 → 正文固定流程/去重/无进展检测 → 运行时预算与最终回答 → 单轮上下文组装。后两项在前两项验收前可先设计，不用扩大步数代替工具修正。

固定回归至少覆盖：19 篇目录、多页目录、空库、目录变化/旧 cursor、超宽问题、单篇和多篇问答、无答案、重复查询、无新增证据、一次模型输出多个工具调用、达到预算、生成失败、恢复后预算不重置、提示注入与越界读取。

分别度量目录完整性/重复率、工具调用数、任务完成率、引用支持、活跃输入大小、实际 token 与耗时。加入 Trace 的 routing、pagination、progress、budget 与 finalization 事件/评分；具体参数和新事件版本在实现时登记。

原 36 次工具调用是一个失败样本基线，不是平均性能。离线回归验证逻辑，真实效果比较需授权固定样例与足够重复运行。获得数据前不宣称“效率提高”或“成本下降”。
