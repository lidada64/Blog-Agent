## 已实现：Agent 主项目

### A1. 从学习 Demo 演进为独立博客助手

- **问题**：早期 Skill Demo 的业务入口与 MCP 依赖不适合作为本地文章问答产品。
- **实现**：抽取共用核心 `code/agent_core/`，业务集中在 `code/blog_assistant/`，独立 CLI `code/blog_agent.py` 提供 qa/manage 入口；旧 Demo 归档保留兼容代码，博客启动无需 Skill MCP。
- **改善**：将工具循环、状态、压缩等机制与文章业务分离，新增博客工具可复用核心；本地产品不再要求启动旧 Skill 服务。
- **证据**：[入口与目录](../../README.md)、[业务包](../../code/blog_assistant/README.md)、[会话组装](../../code/blog_assistant/session.py)、[仓库整理](../repository-layout.md)。独立干净副本 97 项测试通过是 2026-10-11 的历史验收。
- **限制**：当前为本地 CLI；manage 也只读，网站运行时接口未接通。
- **简历表述**：将 Python Agent 学习原型改造为独立博客助手，拆分共用运行核心与文章业务模块，复用多轮工具调用、状态恢复和上下文管理能力，支持不依赖 Skill MCP 的本地问答入口。

### A2. 可定位、可核对的本地文章检索

- **问题**：仅按主题搜索不能处理“找某个文件，再定位关键词”的需求；答案需要可回查的正文依据。
- **实现**：提供 search_posts/read_post/find_file/find_text；正文关键词工具只接受此前文件发现结果。工具返回文章标识、来源、SHA-256 内容版本与行号/片段；限制读取大小和输出预算。2026-10-12 增加 list_posts 元数据分页、范围/快照绑定 cursor 和目录完整性检查；工具查询精确参数复用、按版本/行范围识别无进展、持久模型/工具/搜索/时间预算，以及关闭工具后的最终回答和程序降级。活跃 input 按字节预算选取实际读取证据与完整调用/返回组，完整历史保留。
- **改善**：形成“发现文件 → 定位关键词 → 阅读片段 → 基于来源回答”的工具型本地 RAG 链路。目录问题可完整翻页而无需猜文件名；重复检索和无进展可停止，探索结束不再只返回空答案。恢复沿用本轮已消耗预算，普通模型回复标记 answered_unverified，与目录完成、部分资料、无依据及预算停止分开记录。
  - 同日嵌套读取修复：从仅根层文件扩展至选定知识根目录内的普通子目录，相对路径 article ID 区分同名文件；分页、发现、定位、读取与 Trace 使用同一范围。路径穿越及解析后越界拒绝，目录 symlink/junction 不递归，扫描/文章数量预算保持有界。解决用户文件夹内有文章但工具返回未找到的接口缺口。
- **证据**：[检索实现](../../code/blog_assistant/retrieval.py)、[工具参数与发现结果校验](../../code/blog_assistant/tools.py)、[进度/预算与上下文](../../code/blog_assistant/convergence.py)、[故障与边界回归](../../code/test_retrieval_convergence.py)、[开发说明](../../code/blog_assistant/README.md)、[历史真实样例验收](../../blog-agent-acceptance-20261010.md)。当前 search 是字面量关键词匹配与匹配行数排序；最新回归记录见下方。
- **限制**：未完成统一 Markdown 分块、引用自动验证、向量/混合检索；现有能力已经属于基础 RAG，不能称为向量 RAG。简短目录意图规则不是通用语义分类，正文工具选择仍依赖模型；input 字节限额不是 Provider token 上限。Blog 用户轮次使用本地证据组装，暂不执行远程摘要压缩；真实质量、成本及平均耗时改善尚无对照数据。
- **简历表述**：实现受限 Markdown 目录内的工具型 RAG，返回来源、版本和行号；补齐可验证完整性的目录分页、重复检索复用与无进展停止，持久化请求/工具预算并预留最终回答，支持中断恢复后的预算延续与明确降级。

### A3. 应用执行层权限与资源隔离

- **问题**：模型生成的工具名和参数不能直接视为执行授权；路径与会话恢复也可能绕过资源范围。
- **实现**：执行层工具白名单、参数校验、解析后路径边界检查；qa/manage 当前均只读；恢复时核对模式和文章来源目录，不静默切换。对越界、未知工具及非法参数有离线回归。
- **改善**：把权限落实到应用代码，约束可调用工具与文件范围，使模型文本不能自行获得写入或发布权限。
- **证据**：[权限表](../../code/blog_assistant/permissions.py)、[路径边界](../../code/blog_assistant/retrieval.py)、[执行器](../../code/blog_assistant/tools.py)、[恢复边界](../../code/blog_assistant/session.py)。
- **限制**：CLI 模式不是身份认证；尚未接入网站 session、审批或发布。现有边界检查不代表已全面消除提示注入风险。
- **简历表述**：在工具执行层实施白名单、参数和路径边界校验，隔离会话模式与知识目录，拒绝越界读取及未授权工具调用，避免依赖提示词约束权限。

### A4. 工具结果持久化与中断恢复

- **问题**：多轮工具调用中断后，单纯重新发送问题难以判断已完成步骤与待执行调用。
- **实现**：保存会话、步骤和工具状态/结果；JSON 通过临时文件、fsync 与原子替换落盘；提供 --resume 及未完成工具处理路径。
- **改善**：恢复时可读取已记录结果并继续待处理步骤，使故障定位和续跑有持久状态依据。
- **证据**：[原子保存](../../code/agent_core/state.py)、[工具执行与恢复](../../code/agent_core/runner.py)、[对话状态](../../code/agent_core/conversation_state.py)、[多轮循环](../../code/agent_core/conversation.py)。
- **限制**：当前业务工具只读；不能据此宣称写操作 exactly-once、发布幂等或分布式故障恢复已经完成。
- **简历表述**：设计持久化会话与工具执行记录，采用原子 JSON 保存并支持中断续跑，通过区分已记录结果与待处理调用，提高多轮 Agent 任务的可恢复性与可排查性。

### A5. 上下文管理与模型用量观测

- **问题**：长对话增加上下文规模，摘要和重试也会产生额外模型开销，不能只统计最终答案请求。
- **实现**：保留原始历史，支持 local/summary 等压缩策略及历史回读；记录请求用途、耗时、输入/输出 token、服务商返回的 cached token 和稳定前缀哈希；缺失或非法缓存计数保留为未知。
- **改善**：区分正常推理与摘要/压缩开销，为成本和质量对照提供观测基础；历史回读让摘要遗漏仍可追溯原记录。
- **证据**：[压缩策略](../../code/agent_core/context.py)、[请求观测](../../code/agent_core/metrics.py)、[成本模块](../../code/agent_core/costs.py)。
- **限制**：策略可用性依赖 provider；用量观测不等于缓存优化已完成。暂无足够重复实验支持“成本降低/响应加速”的结论。
- **简历表述**：实现可配置上下文压缩与原始历史回读，采集模型请求耗时、token、缓存命中和摘要开销，为长对话成本与质量评估建立观测基础。

### A6. 统一离线回归入口

- **问题**：工具边界、恢复与压缩容易在业务迁移中回归；付费模型调用不适合每次改动都执行。
- **实现**：统一 `python code/evaluate_agent.py --mode offline`，测试使用临时文章和模拟模型，输出 JSON/Markdown 报告；核心和博客测试从同一入口发现执行。
- **改善**：在不发送用户正文、不调用付费模型的情况下检查核心回归，并保存可复查结果。
- **证据**：[评测入口](../../code/evaluate_agent.py)、[评测逻辑](../../code/agent_core/evaluation.py)、[任务验收](../TASKS.md)。最新本轮结果见下方验证记录。
- **限制**：离线用例通过不能证明真实问答准确率；Trace grading v1 已补齐基础过程评分（见 A7），完整 RAG 质量系统和语义校准仍待实现。
- **简历表述**：建立覆盖共用核心与博客业务的统一离线评测入口，使用临时知识样例和模拟模型验证工具边界、状态恢复与上下文行为，输出可复查的结构化报告。

### A7. 本地 Trace grading v1（2026-10-12）

- **问题**：仅看最终回复难以区分工具选择、权限、来源、状态恢复或预算失败；结构通过也不能代表任务目标完成。
- **实现**：共用核心采集实际模型/工具/权限/轮次/压缩/恢复事件，Blog-Agent 默认启用；本地版本化 Trace 与可配置规则评分器，分 structure/safety/task/budget 四维，输出 JSON/Markdown、失败类别和证据 ID。参数校验复用运行代码，工具结果保存摘要哈希，检查点与 rubric 支持确定性重评。
- **改善**：从最终输出检查扩展为过程定位，能检测丢失返回、错误来源版本、越权成功与预算超限；预期拒绝显式配置；没有任务断言时返回 NEEDS_REVIEW，缺失用量为未知。Trace 默认仅元数据，评分不执行模型/工具。
- **证据**：[使用与评分规则](../../code/evals/trace-grading.md)、[评分器](../../code/agent_core/trace_grading.py)、[故障回归](../../code/test_trace_grading.py)。新增 15 项测试，统一 112 项离线回归通过，报告位置见验证记录。
- **限制**：本地确定性规则版，未接入托管平台或 LLM judge；未完成语义引用评分、完整 RAG 评测与费用对照；不宣称问答准确率或成本已有提升。
- **简历表述**：为 Python Agent 建立本地 Trace 采集与规则评分系统，关联模型请求、工具执行、权限和恢复事件，按过程完整性、权限、任务目标及预算定位失败，并用故障注入验证评分器对异常轨迹的检测能力。

### A8. 跨轮状态隔离与截断恢复（2026-10-12）

- **问题**：失败收尾的旧步骤被新问题复用，文件定位占用正文搜索配额，模型截断缺少原因观测；旧会话提示词难以确认版本。
- **实现**：步骤复用绑定当前未完成轮次；新轮分项持久预算兼容旧共用预算；提示词版本/hash 与轮次边界显式升级；记录截断原因、输出上限及可观测推理用量，最多一次预算内无工具重生成，区分生成失败与预算停止并列出已读来源。
- **改善**：在离线复现中纠正新轮工具与 Trace 归属，避免定位工具耗尽正文读取机会；恢复不会重置预算或截断重试次数，用户历史会话不被静默修改。
- **证据**：`code/test_budget_state_repairs.py` 新增 15 项；统一 171 项回归通过，报告 `code/eval_results/20261012T060511444807Z/report.md`；代码位于 conversation.py、metrics.py、blog_assistant/session.py、convergence.py。
- **限制**：旧损坏步骤保留历史，未自动修写用户检查点；旧 v1 当前轮维持原配额。固定证据样例验证输入保留，真实问答准确率、复杂阅读配置与成本改善仍待验证。
- **简历表述**：修复可恢复 Agent 的跨轮步骤归属错误，实施兼容旧检查点的分项预算与提示词版本管理；为输出截断补齐用量观测和有界恢复，通过故障回归验证中断后预算及重试约束持续有效。
