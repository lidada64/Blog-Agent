## 亮点表述规则

每次完成相关功能、修复或实验，同步更新本文件：**问题 → 实现 → 改善 → 证据 → 限制 → 简历表述**。更新已有条目优先于重复追加。未完成的能力放在待办区，不能混入已实现成果。

- 实现事实依据代码；通过结论注明验证日期、环境和范围。历史验收与本轮复测分别记录。
- 没有前后对照时写具体能力变化，例如“增加中断后的恢复入口”，不写“效率提升 50%”。测试数量不能替代问答质量或生产可靠性。
- 性能、成本、准确率提升须附基线、固定任务集、模型/配置、样本数、完整结果及缺失数据；每组至少 5 次的实验要求沿用实施计划。
- 每条简历表述都要能解释实现机制、失败场景、取舍及个人实际承担的工作；投递前确认个人贡献，避免把 AI 协助实现夸为全部独立完成。
- 原始文章、凭据、会话和评测输出保留在被忽略的本地目录；这里只记录可公开的结论和证据入口。
