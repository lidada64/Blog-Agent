### 主要原因：章节模型与引用协议不一致

1. `sections.py:sections`识别各级Markdown标题，却只保存title/start_line，不保存标题层级与父子关系。每节范围一律到下一个任意级标题前一行。对RAG局部块可以有用，却被`section_citations.py:audit_sections`直接用来代表“可引用章节”。父节的子节正文被排除。
2. 目标文章“怎么做系统设计”范围37–40，下一行是子标题“**方法论：**”；“数据库”范围181–184，随后进入子节。两段仅有标题与空行。audit_sections筛掉标题和空行后selected为空，即抛section_not_read。全文已读、父标题真实存在、子节有正文，仍被错报未读。
3. 标题比较要求`s['title'] == section`。解析器去掉外层#，保留行内**；模型输出带“##”的平衡标题失败，去掉##即通过；“方法论：”失败，保留“**方法论：**”才通过。人类语义等价的展示写法被当成不同来源。此处没有安全的规范化或稳定章节ID，生成模型承担了内部地址序列化工作。
4. 任一来源失败都会把整篇草稿替换成固定拒答；第5轮10处来源8处located、2处invalid仍整体拒绝。对未知来源保持保守合理，但此处把解析结构/拼写错误与缺依据合并处理，没有区分可修复错误，反馈反而要求用户明确文章。
5. 最后一轮只剩1个顶层来源且通过。顶层“系统架构设计”节按当前切分只有1–16行，其中3行非标题正文；审计semantic_support始终为null。这意味着程序只确认引用能定位，没有证明长答所有断言受该节支持。全文可见不代表这条引用范围覆盖长答；不能把located称作语义认证，也不能据此断言长答事实错误。

### 重试为何没有自行恢复

`convergence.py:retry_citations`临时算出audit后只设置citation_retries=1，没把具体失败章节、原因、合法引用候选写入下一次输入。`request_options`只追加“上一回答来源未通过核验，重新回答”的通用提示并关闭工具。`TaskContextBuilder.build`一般只保留带完整tool call/output的当前轮协议组，单独失败草稿没有对应调用时被省略。

模拟真实循环确认：两个请求，第二次有通用修复提示，但input既无section_not_read具体原因，也无失败草稿标识；再次整体拒答。这里是“修复上下文缺少诊断反馈”，与“文章正文context不足”不同。模型无法稳定知道应改父节引用、去掉#还是保留**；重新生成仍可能撞同一限制。本轮未重新运行真实模型，无法从离线模拟推出具体模型再次成功概率。

### 参考改进方向（未实施）

先分离检索chunk与引用section：后者保留标题级别、父子关系与稳定ID，父节覆盖其子树；仍核对真实可见范围，不能只因读过标题就信任全文。提供source/section manifest和内部引用ID，由程序渲染用户可读文章/章节；显示标题的轻量规范化必须处理重名歧义，不模糊接受虚构来源。区分unknown_section、section_has_no_direct_body、source_not_visible、stale等错误，把失败引用及合法候选反馈给预算内修复。仅在确有足够已读正文时选择文章级引用；不能用宽泛标记替代语义支持验收。保留安全拒绝，同时把系统格式错误与用户问题含糊分别告知。验收覆盖嵌套空父节、粗体标题、带#、同名标题、部分读取、失效来源、正确标题重复提问；分别评分召回、证据可见、引用解析、断言支持及回答可用性。
