## D11 / D12 · 简单问题误拒与旧回答摘要重复的回答契约修复

- 日期/执行者/状态：2026-10-13用户反馈并认领，2026-10-14用户要求继续；AI实施与离线验收。沿用D11/D12，D7选题边界关联本条，不重复编号。
- 分级：D11 M/F/D/U=2/2/2/0，6分L2；实际路由/共享循环/任务投影/检查点接口协同，沿用008一次复发追问及本次简单问题误拒反馈，原因高置信，未称大难题。D12仍3/2/3/0，8分L3，沿用既有跨子系统与多次澄清依据，不补造全历史统计；本条只解决旧回答改写子项，候选/阶段及开放题质量仍待验。

### 现象与根因

用户报告1+1被文章来源门禁替换，参考旧MCP回答的一句话总结又读文章并重复长答。实际只读检查点的第8轮“按照之前回答总结MCP”被绑定新task:8，消耗5次生成请求与5次工具（两次历史、文件发现、搜索、全文读取）；此前第3轮已读并回答MCP。引用定位有效不能代表完成用户要的总结。

原契约只有help/catalog/qa，普通问题默认文章事实；历史投影主动隐藏助手回答，TaskContextBuilder匹配候选元数据而非真正回答过的来源，中文紧邻ASCII标题也被Unicode词边界排除。用户请求的格式没有应用级完成标准。产生“错误任务→无依据拒绝”和“丢目标回答→重复检索/长答”两条失败链。

### 尝试过程

1. AI在真实Conversation/BlogStore缝隙建8项回归，首跑5失败、3通过，日志保留`.blog-agent-data/answer-contract-red.log`。分别验证任务类型/门禁误用、旧回答没有进入输入、只给资料没有约束输出格式，不直接全局关闭来源守卫。
2. 增加answer_contracts.py：article/runtime/calculation/conversation/rewrite/clarify与对应证据类型持久化。身份/能力用运行事实，四则用受限AST/Fraction精确验证（有限表达式、除零/超限明确拒绝，不eval），上一轮用户输入依据本会话元数据；不以模型自称常识放行文章事实。新增契约通过.13显式启用，.11/.12工具/章节/任务记忆仍兼容，旧轮不自动换策略或增额。
3. 旧回答定位采用真正完成轮的已引用文章/标题，避免候选目录污染；只带入该轮可见回复，不存或总结用户模型隐藏推理。文章来源重验权限/版本/可见范围，资料完整时工具表关闭且执行层也拒绝重查。简单本地回答可依conversation_metadata改写，不附伪文章来源。
4. 首轮新契约8项中2项仍失败：中文“总结mcp”不满足ASCII标题的Unicode词边界。改为ASCII标识符边界并回测，契约/原回答策略/任务上下文共37项通过。保留失败日志，不将正则补丁当作全部方案。
5. 一句话/简短总结增加完成检查；首份长答只在原请求/时间额度内重试一次，再次不满足时format_unverified，不能说文章来源失败或继续展示旧长答。旧来源失效、旧回复本就失败、无对应主题、旧答装不下分别明确部分资料/澄清；新能力不授予发布/编辑权限。
6. 扩为21项，包含切题返回、候选污染、中英文回复/解释指代、默认简短摘要、数学自然问法/小数/除零、旧.12与显式升级、格式重试后取消恢复、更新/删除/权限撤回、长输入及修改计算检查点拒绝。新增21项在开发Python3.12与用户Python3.10环境均通过；全量结果见下。

### 实际会话只读回放与验证

原qa状态仅深复制到临时目录并显式升级副本；使用实际旧来源和模拟生成输出，选中第8轮真实可见MCP回答，旧回复进入input、tools=[]、新增读取/搜索/历史调用0，只需1次模拟生成；随后1+1本地返回2，新增模型请求0。原检查点字节hash不变。脚本`.blog-agent-data/answer-contract-replay.py`只输出元数据；该次数证明执行策略，不是付费模型真实质量或成本收益。
