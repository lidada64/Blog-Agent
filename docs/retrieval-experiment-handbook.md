# 读取、检索与多篇问答实验手册

版本：v1，2026-10-12；进度更新至 2026-10-13。关联难题：D9。状态：D9 固定三题真实交付与可信引用验收已完成；EXP-0/1 离线基础、EXP-2 K0/K1 离线对照及 EXP-3 固定证据模拟已完成，语义/混合检索与真实 Subagent 对照尚未验收。

本手册让新对话能认领一个明确实验，先开发离线验证，再在已授权条件下比较真实质量与费用。它不将现有 171 项离线通过解释为真实问答质量，不将方案记录解释为 D9 已修复。问题原始经过只维护在 [唯一台账 D9](project-highlights/README.md)，研究来源见 [一手资料笔记](retrieval-experiment-sources.md)。

## 1. 新对话从这里开始

1. 读取本仓库 AGENTS.md、docs/TASKS.md、台账“下次会话优先”和 D9；实现时读本手册相关实验及实施计划 §24/26，核对当前源码，保留工作区既有改动。
2. 查找本地实验目录的 manifest 与记录；有未完成实验时续接它，核对代码、数据、模型与配置版本。配置变化新建实验 ID，不把两种配置混进同一组。
3. 先认领一个下面的 EXP 阶段，更新 TASKS。本轮写清输入、产物和完成门槛；默认使用合成/临时文章、模拟模型、只读权限。用户原会话保持原样。
4. 离线门槛通过后，核对已有授权的 provider/model、数据范围、样本数、金额/请求上限和是否允许 embedding 外发；缺少时只问缺项，同时继续离线工作。已有明确授权写入 manifest，跨对话沿用，不反复要求批准同一范围。
5. 报告写入忽略的运行目录，公开结论与限制回填台账 D9；更新本手册的进度表和下次第一步。运行代码修改后执行统一离线回归，网站实际修改才增加其类型/lint/build、页面/数据验收。

建议首次开发请求：**“按手册 EXP-0 开发临时语料和统一证据/指标契约，离线复现 D9 并冻结数据集；本轮不调用付费服务。”**

## 2. 本实验要回答的三个问题

**Q1：不同大小和任务应该返回全文、章节还是段落？** 大小不仅看行数，还看实际序列化输入、正文语言/格式、证据总量和模型输入空间。最终产物是可解释、可配置的分支规则和经验证的阈值，不是凭直觉设一个“短文”的常量。

**Q2：关键词段落、语义段落与混合检索，哪种在本项目更划算？** 比较整段任务的费用、耗时、质量和失败恢复，加入索引建设/更新的摊销。关键词法作为持续可用的基线；embedding 与重排都不是默认胜出。

**Q3：复杂问题和多篇引用何时值得用 Subagent？** 单 Agent 为默认基线；多篇来源数只是负载特征，不能单独作为触发器。子任务只有取得可核对质量/耗时收益且满足总预算时才启用。

### Subagent 的讨论结论与待验证条件

“比较三篇短文的共同观点”通常先测单 Agent 批量取证和统一写作。“分别调查多个独立主题，再综合异同”可能适合独立子任务。“两篇长文给出冲突结论”可能适合引用/矛盾核查子任务。文章很多但每篇只需一小段时，应先测检索器一次组装证据，不能把小粒度工具问题转交给更多 Agent。

拆分的成本包括子任务指令、独立上下文、检索和生成、父任务核验与最终融合；并行可能缩短墙钟时间，却不自动减少总 token 或费用。原 D9 的恢复预算不足不能靠多 Agent 回避。无论子任务数是多少，都只能由父任务生成一份面向用户的连贯回答，不能直接拼接几份独立摘要。

业务 Subagent 只接收子问题、必要证据、来源版本和最小只读权限；返回结论、支持片段、引用、冲突和未知点。父任务可核对实际片段，不把子任务断言视为已证实事实。优先测试一个引用核查者，随后最多两个独立检索子任务；这些数量是待测实验配置，不是新的产品默认。

## 3. 先冻结共同条件，避免把多个改动混在一起

每组固定 provider/model 的实际标识、提示词/hash、推理配置、输出额度、总模型/工具/时间上限、输入预算、缓存条件、语料/分块版本、查询与评分标准。候选间改变一个因素：先读取方式，再检索排序，再推理/输出配置，再 Subagent。记录工具 schema 变化引起的前缀/缓存变化；不要假装不同 schema 的服务端缓存完全一致。

原始 D9 用于故障回放：331 行/约 5,892 字符文章被读七次，八次请求的最后回答截断且无恢复额度；详细用量见台账。合成同尺寸语料复现接口/预算逻辑即可，不能自行发送原用户正文。D9 原始策略只作为历史失败对照；公平成本实验使用同一修复后的回答/恢复预算，并对各检索方法保持相同配置。

所有候选须在持久总额度内留出最终回答和最多一次恢复。可离线先测试“总请求 8，探索最多 6，回答 1，恢复 1”的配置；该数值仅为初始实验点，真实阈值经数据确定。配置改变后继续原检查点不能重置消费，父子共用同一个总账本。恢复失败明确保留未回答任务和证据，重试入口继续同一任务；来源清单、预算降级与正常完整回答分别计分。

可见回答完整性与输出额度单独测。初轮方法比较沿用相同配置，随后才在胜出方案上单因素比较 provider 实际支持的推理强度和输出额度；不默认 high 必要，也不把增额后的成功归功于检索升级。

## 4. EXP-0：统一证据与实验驱动（先离线）

目标：让各候选产物进入同一生成/评分通道，形成可重复输入输出；本阶段不实现业务 Subagent 或发送用户资料。

证据记录至少包含 article_id、chunk_id（全文也有 ID）、标题/章节、source、内容版本、可见性、起止行、原文、实际字符/UTF-8 字节数、token 计量方法和完整性。全文/章节/片段模式明确标记；无法完整交付时返回原因和剩余定位，不能把截断文本当全文。每个结论可追溯实际交付的来源/版本/行号。保持文件发现前置、目录/权限校验与工具调用返回配对。

生成输入统计实际序列化后的整包：系统指令、工具 schema、必要历史、问题、证据及包装。正文在证据摘要和工具结果中重复出现会放大输入，应测量重复占比；去重保持调用/返回完整和可回查原始证据。对上下文去重的修改另建实验因素，不能混入首次检索排序比较。

驱动拆分两个阶段：先返回可独立评分的检索结果，再使用同一生成器给出答案。固定检索路径作为基线；允许一次补查的自主路径单独作为后续对照。失败、取消、空结果、未观测 usage 均进入报告，驱动隐式 API 重试关闭或逐次显式计量。

**完成门槛**：驱动在临时文章和模拟模型上覆盖 D9、无答案、超长输入、非法路径、草稿/版本失效、恢复不重置；输出 manifest、逐请求记录、证据清单和独立检索/回答评分。统一离线回归通过；更新 §1 的真实可执行命令。

## 5. 固定数据集与人工标注

先建立至少 18 个合成或已授权任务：6 个调参、12 个封存验收；按问题族分割，相同模板改写不能泄入另一侧。每组真实配置每题至少重复 5 次，复用旧计划的要求；先用调参集筛出最多两种候选再开展完整真实验收，按 manifest 计算总调用上限，不把全部笛卡尔积直接交给 API。

| 任务族 | 必须包含的情形 | 预先标注 |
| --- | --- | --- |
| 单篇概念解释 | 正确术语、拼写错误、同义表达 | 定义、机制、例子、适用边界及所需片段 |
| 阅读大小 | 很短文、D9 稀疏 331 行、长单行、长文相关内容在末尾 | 可读范围、全文是否必要、不能遗漏的依据 |
| Markdown/语言 | 中文、英文、混合；完整代码块/表格/引用 | 块边界、引用位置与不可割裂内容 |
| 多篇综合 | 2–3 篇短文、独立子主题、多跳关联 | 必须来源、关联链及综合结论 |
| 冲突与无答案 | 新旧版本冲突、证据不足、完全无答案 | 应呈现差异、限制或拒答，禁止编造 |
| 安全与恢复 | 正文诱导、越界、更新/删除/撤回、截断/断连/重启 | 预期拒绝与终态、预算守恒 |

各题保存 question_id/family、来源及版本、允许可见范围、必须事实和支持范围、禁止结论、可回答性、任务期望和评分 rubric。检索调参与冻结后才能看验收集。临时夹具大小可按估计 token 分层，同时保留字节/行数；覆盖相同字数不同排版和相同行数不同字数，才能判断行数限制的影响。

初版可试正文约 1k/4k/8k/16k estimated token 的四档；这是取样坐标，不是接受任意 16k 输入的承诺。provider 缺少适配 tokenizer 时明确使用估计，字节上限与已观测 usage 分开报告；不能把字符数除以固定常量当实际计费 token。

## 6. EXP-1：全文、章节、段落的阈值与分支

比较 R0 当前按行读取、R1 有界全文、R2 按 Markdown 章节、R3 多片段/多篇批量读取。文件原有大小限制保持；批量限制总证据量且逐项校验权限。程序内部批量读文件无需创建子 Agent。超长单行、完整代码/表格跨块时有明确处理，不静默破坏语义。

计算可交付证据空间：provider 总上下文空间扣除实际指令/工具/历史/问题及输出预留，再与应用 input 字节限制共同约束。恢复另记请求/时间额度；不能将输出 token、输入字节、模型请求次数混作一个预算。若 API 的总上下文计量未知，使用保守应用限额并报告边界，不能声称已验证 provider 硬上限。

路由先通过明确用户要求和可观测元数据决定：

| 条件 | 待测返回方式 | 不能忽略的判断 |
| --- | --- | --- |
| 指定短文全文/整篇总结，整包能容纳 | 有界全文 | article/版本、完整性与生成空间 |
| 指定长文某章节或范围 | 完整章节/显式范围 | 完整代码/引用与相邻定义 |
| 概念解释/事实定位，全文虽能容纳 | 全文 vs 相关段落做对照 | 能装下不等于全文成本最低 |
| 多篇短文比较，总量能容纳 | 一次批量全文或章节 | 必须来源覆盖、总体去重 |
| 长文或多篇总量超预算 | 分块检索并一次组装证据 | 冲突/多跳证据不能仅按相似度删除 |
| 明确全文要求但超限 | 告知范围并采用有界章节流程 | 不能假称读完；需要澄清时说明原因 |
| 文件过期/不允许/无依据 | 刷新、拒绝或明确资料不足 | 不以换模式绕过权限，不假引用 |

阈值离线扫描：用可用证据空间的 25%/50%/75% 三档作为全文上限候选，连同绝对整包上限同时检查；每个候选在固定大小/排版任务上测请求、证据完整性和峰值输入。章节/段落长度候选也只在调参集筛选。估计触边时退回更保守分支，记录路由原因。分支边界测试阈值以下/等于/以上，以及单篇合格但多篇合计超限。

**完成门槛**：在冻结集上输出任务族→路由→阈值→失败/回退表；D9 形状短文可一次交付全文或一次组装足够证据，无逐段自主续读，失败时可在同一任务恢复。选型以质量门槛后全任务成本为准，保留显式范围读取给精确定位需求。

## 7. EXP-2：关键词、语义与混合检索成本对照

关键词段落检索本身已属于 RAG，不需要先购买 embedding。所有方法使用同一 Markdown 分块/权限/版本/输出证据契约，保持父模型、生成输入预算和补查规则相同。分块初筛可试 300/600 estimated token、0/15% 重叠；标题/代码完整性优先，规则冻结后再比较排序方法。

| 方法 | 待实现实验能力 | 对照意义 |
| --- | --- | --- |
| K0 当前关键词匹配 | 保留作历史基线 | 区分分块与排序带来的收益 |
| K1 关键词段落（可评估 BM25） | 一次返回有来源的相关段落 | 不用 embedding 的成本/质量基线 |
| S1 语义段落 | 文档分块 embedding、查询 embedding、相似度 | 单独测同义/跨语言召回改善 |
| H1 混合 | 相同 K1 与 S1 候选，固定融合/去重 | 测精确术语与语义信息互补 |
| H2 混合 + 重排 | 仅 H1 有遗漏时再测 | 重排额外费用/耗时能否换质量 |

关键词初筛可试 Top-K=3/5、每篇上限=2/3；混合融合可评估固定 RRF 参数并写 manifest。相似度没有通用可信阈值，各法在调参集上冻结选择规则。保留标题、章节、版本与必要邻段；跨文章问答标注的事实覆盖不足时允许一次明确补查，费用照计。先测离线检索命中，再让最多两种合格候选进入真实生成验收。

以“索引已热”比较每次问答，以“从空库建索引”比较首次成本；另测单文更新、删除/撤回和重建。仅版本变化的块重算 embedding，重复运行命中可观测缓存；语料更新后的片段不能保留旧权限或旧正文。索引存储/模型与 SQLite/元数据计划协调，新增依赖单独评估；本手册不预选向量数据库或 embedding 服务。

**完成门槛**：每个任务族给出 K1/S1/H1 的召回、回答、引用、费用、耗时和索引成本；结果可选择纯关键词、按任务路由混合或暂不启用语义，不强迫一个全局赢家。测试集不达标或没有可证明收益时保留 K1 路径，记录 S1/H1 失败原因。

## 8. EXP-3：Subagent 单因素对照

在 EXP-1/2 获得稳定单 Agent 基线后，固定同一检索/证据包/总预算和质量集，比较 A0 单 Agent（包括已经优化的批量/并行工具）、A1 父任务+一个引用核查者、A2 父任务+最多两个独立研究子任务。若独立检索确有价值，另外做端到端检索对照；不能把固定证据核验实验与自主检索实验混为同一收益。若相同小额度内 A2 无法完成，先如实报告，再在预先授权的较大总额度上同时重测 A0/A1/A2，形成质量—成本曲线；不同额度的样本不能当相同资源比较。

总资源上限相同，子任务预算从父任务探索额度划出，并由执行层原子预留；父任务回答/恢复额度不被子任务占用。子任务重试/取消/恢复继承账本与截止时间；总并发限制清楚。子输出原文引用、未知点、证据 ID 与版本均由父任务验证，任务超时/无效产物可受控回退，但回退费用计入总账。原先单 Agent 八次调用与三个 Agent 各八次不能比较成相同预算。

父任务最终回答包含一个统一的论述顺序，明确不同来源的共同点/矛盾和原文与推断；独立结果不能直接串联。攻击/越权子任务、缺失来源、错误引用、父任务未核验、子任务失败以及中途重启均为离线故障用例。

**启用门槛**：在独立复杂任务族中，A1/A2 的事实覆盖或冲突识别有稳定改善且费用在预设上限内；或质量相当、墙钟时间改善达到预设门槛。简单问答与短文对比出现额外成本无收益时仍走 A0。有证据前只提供显式开关，自动触发器基于任务可拆分性/证据负载/预算，不由“文章数≥N”单独决定。

## 9. 完整成本和质量判定

每次 run 保存模型请求数、工具次数、input/output/reasoning/cached token、峰值序列化 input bytes、重复证据占比、墙钟/首个有效答案耗时、恢复次数与终态。所有来源、回答与原始运行输出留在忽略目录；公共报告只保留脱敏结论。

费用按服务实际账单语义计算：每个模型请求的非缓存输入费+缓存输入费+输出费（包括该服务已计入输出的推理量）；再加 embedding/重排/摘要/父子任务/所有重试及失败费用。将价格币种、计费单位、provider/model、取得日期和来源 URL 冻结到价格快照。不要拿旧 Demo 的其他模型价格表套用；缺 usage 或价格为 unknown/incomplete，不能自动变成零费。

`在线任务成本 = 该任务全部服务费用`；`摊销成本/问答 = 在线成本 + (首次建索引成本 + 更新成本)/假设问答数`。报告假设 10/100/1000 次问答下的敏感性，不把假设使用量写成真实流量。本地模型/检索记录硬件、内存、CPU/GPU 秒和运维成本范围，“没有外部 API 账单”不等于总体免费。

最少报告：成功与失败各自费用、每次尝试平均费、`全部尝试总费/通过质量门槛的任务数`（分母为 0 时为未知/不可用）；保留所有样本和失败。每题配对比较候选，交错运行并记录冷热/顺序。不能清空服务缓存时说明限制；均值/中位数/范围并列，五次重复仍不支持夸大统计确定性。

### 开跑前冻结的初版质量门槛

这些是待确认的实验起点，在 EXP-0 manifest 中冻结；改门槛新建版本、重评所有候选，禁止看结果后放宽。

- 安全拒绝、范围/草稿隔离、来源 ID/版本/行范围真实、持久预算不超额：100% 固定故障用例通过；一例泄露或虚构引用就阻断发布。
- 普通可回答任务：至少 90% 给出包含必须事实的解释；固定的简单概念及 D9 用例必须完成，不能只返回来源。无答案/冲突任务按标注正确说明限制，不强求编出答案。
- 人工引用支持：至少 95% 的带引用可核对断言得到原片段支持；数字是小样本门槛，逐断言记录分母，不能只报一个百分比。
- 连贯性：0=无答案/来源清单；1=碎片罗列/矛盾未解释；2=主问题回答但缺关键关系；3=有清楚顺序、来源区分及必要关系；4=解释完整且例子/限制有依据。合格至少 3，覆盖定义/机制/例子按各题 rubric 判定。
- 检索 Recall@K、MRR 按标注证据计算，必要多跳/冲突来源覆盖单列；没有统一 chunk 可比性时对来源/行范围覆盖计算。关键词 vs 语义方法比较在同一分块上进行，跨分块配置按事实覆盖评价。
- 评分默认用人审+确定性校验；LLM judge 仅在另有授权时辅助，并计费用、保存校准。模糊/冲突标注复审，关键词出现或 Trace PASS 不能当答案合理。

先淘汰不合格候选，再比较合格方案的质量、费用与耗时。若费用差异不明确优先较简单稳定方案；若质量与速度交换费用，以用户预设限制报告 Pareto 选择。没有任何候选过门槛就继续诊断，不宣布一个失败最少的赢家。
